# Evidence

Every quantitative claim in this skill, with its source and its limitations.
A skill that flags unbacked claims should be able to back its own.

## Industry-scale code quality trends

**GitClear, "The Maintainability Gap: AI Code Quality in 2026."** 623 million
analysed changes, 2023-2026, across commercial and open-source repositories.

| Signal | Change |
|---|---|
| Block duplication (5+ repeated lines) | 40.3 → 73.0 per million changed lines (+81%), record high |
| Within-commit copy/paste | 9.4% (2022) → 15.7% (H1 2026), +41% |
| Moved (refactored) lines | 21% (2022) → 13% (2023) → 3.8% (2026 YTD), −70% |
| Cross-file function connectivity | 343 → 223 calls per thousand changed lines, −35% |
| Long-term legacy maintenance | 1.7% → 0.46% of changes, −74% |
| Error-masking constructs | +47% |
| Two-week code churn | +15% |

Developers now duplicate rather than refactor at roughly 5:1, having preferred
refactoring 2:1 in 2022. The predecessor report (Feb 2025, 211M changed lines,
2020-2024) found 2024 was the first year on record where copy/paste exceeded
moved code, with an eightfold rise in duplicated blocks.

*Limitations:* GitClear sells code-quality tooling, so there is a commercial
interest in the finding. The metrics are proprietary classifications of git
operations. Roughly half of conventionally-counted changed lines are excluded by
their filters. The trend is correlational — AI adoption is not isolated from
other industry changes. Direction is consistent across seven independent signals
and multiple years, which is what makes it credible despite the above.

## Agent degradation over iteration

**"SlopCodeBench: Benchmarking How Coding Agents Degrade Over Long-Horizon
Iterative Tasks"** (arXiv 2603.24755). Agents repeatedly extend their own prior
solutions under evolving specifications.

- No agent solved any problem end-to-end. Best per-checkpoint strict solve rate
  14.8-17.2% depending on version.
- Structural erosion rose in 77-80% of trajectories; verbosity in 75.5-89.8%.
- High-complexity functions per codebase: ~4.1 → ~37.0 across a trajectory.
  Peak cyclomatic complexity ~27.1 → ~68.2.
- Agent code 2.2-2.3x more verbose and ~2x more eroded than maintained human
  repositories, with the gap widening each iteration. Human repos stayed roughly
  flat.
- Quality-focused prompting reduced *initial* verbosity and erosion by up to a
  third but did not change the degradation rate — "shifts the intercept but not
  the slope."
- Pass-rate metrics miss it entirely: core tests stayed passable while
  error-handling and regression tests collapsed; core tests became up to 13x
  easier to pass than the full suite by the final checkpoint.

*Limitations:* Two versions of the paper report slightly different figures
(11 vs 15 agents; 48 vs 473 comparison repositories), so treat individual
percentages as approximate and the direction as robust. Synthetic problems, not
production repositories. Verbosity is operationalised via AST pattern density,
which is a proxy.

## Capability does not reduce defects

**"AI-Generated Smells: An Analysis of Code and Architecture in LLM- and
Agent-Driven Development"** (arXiv 2605.02741, Concordia University). Two
experiments: single-file algorithmic tasks across five models, and multi-file
systems generated by a multi-agent framework.

*Reasoning-complexity trade-off.* Long Method violations, zero-shot: Qwen-Coder
480B produced 11, Gemini 2.5 Pro 5, human baseline 1. Llama-3-70B produced 0 —
because it failed before generating enough code to trip a length threshold, not
because it wrote better code.

*Machine signature.* Humans produced state-management smells (Temporal Field: 4
instances, absent from every model's output). Models produced procedural smells.
The defect profile differs in kind, not just degree.

*Prompting does not fix it.* Structured few-shot prompting with explicit
standards and boilerplate *increased* Long Method violations: 11 → 13 for
Qwen-480B, 5 → 8 for Gemini 2.5 Pro. Across four escalating requirement-
specificity stages, specificity had no statistically significant effect on any
smell category (p > 0.8).

*Volume-Quality Inverse Law.* Total lines of code correlated with architectural
smells at ρ = 0.94 (p < 0.001), structural at 0.59, code-level at 0.53. File
count with architectural smells at 0.72.

*Taxonomy shift with scale.* Single-file work produced Long Method. Multi-file
systems produced God Class (Too Many Branches, high Response For a Class),
redundant inline reimplementation, and the "Modular Mirage" — files split
without semantic cohesion, so structure looks modular while related behaviour
scatters.

*Limitations:* This is the load-bearing source for the capability claim, and its
model set is Gemini 2.5 Pro plus open-weight models (Qwen, Llama, DeepSeek) — no
Claude, no GPT-5-class model. The "more capable is worse" finding is within that
cohort. 90 problems; small n. The multi-agent experiment uses a single framework
(MetaGPT), so architectural findings may partly reflect that framework. No
iterative debugging loop, so results reflect first-pass tendencies.

Treat the *direction* as well-supported — it agrees with SlopCodeBench, which
did test frontier Claude and GPT models — and the specific ratios as indicative.

## Package hallucination / slopsquatting

**Spracklen et al., "We Have a Package for You!" (USENIX Security 2025).** 16
models, 576,000 code samples, 2.23 million package references. 440,445 (19.7%)
were hallucinated, spanning 205,474 unique non-existent names. Commercial models
≥5.2%; open-source 21.7%.

**Churilov, "The Range Shrinks, the Threat Remains" (arXiv 2605.17062).**
Replication on five frontier models released Oct 2025 - Mar 2026, 199,845
generations:

| Model | Hallucination rate |
|---|---|
| Claude Haiku 4.5 | 4.62% |
| Claude Sonnet 4.6 | 5.41% |
| Gemini 2.5 Pro | 5.80% |
| DeepSeek V3.2 | 5.89% |
| GPT-5.4-mini | 6.10% |

The inter-model spread compressed 11-fold, from 16.5 points to 1.48. But no 2026
frontier model beat the best 2024 commercial result (3.6%), and 127 package
names were invented *identically by all five models* across four vendors — 53 of
which remained registrable after registry-side defenses. Python rates now exceed
JavaScript, inverting the 2024 finding.

The convergence is the important part: a single malicious registration can
target users of every major provider simultaneously, and using a different
vendor's model is not a mitigation.

Most-frequent universal confabulations include `aws-cdk` (real package is
`aws-cdk-lib`), `rest-framework` (`djangorestframework`), `opengl`
(`PyOpenGL`), `tencentcloud`, and `mpl-toolkits` (a matplotlib submodule, not a
package). The pattern is a plausible-but-wrong name adjacent to a real one.

*Limitations:* The replication is a single-author independent preprint, not
peer-reviewed. It notes that agentic configurations with tool use and retrieval
— Claude Code, for instance — were **not** tested, and retrieval could in
principle eliminate the failure entirely. GPT-5.4-mini ran at minimal reasoning
effort with a 32% refusal rate, creating denominator asymmetry. Rates may be
biased downward if the 2024 prompt corpus leaked into 2026 training data.

Reasonable reading: package hallucination is real and persistent in raw
generation; an agent that can check a registry should be trusted more than a raw
completion; verification remains cheap enough that there is no reason to skip
it.

## Verification burden

**Sonar, 2026 State of Code survey**, 1,100+ professional developers: AI accounts
for 42% of committed code, expected to reach 65% by 2027. 96% do not fully trust
AI-generated code; only 48% always verify before committing; 38% say reviewing
AI code takes more effort than reviewing a colleague's.

**CodeRabbit (Dec 2025):** approximately 1.7x more defects per pull request in
AI-generated code.

*Limitations:* Both are vendor-published. The Sonar survey is self-reported. The
gap between "42% of code is AI-written" and "48% always verify" is the structural
argument for automated gating, independent of the exact figures.

## Tool behaviour

Measured directly on a controlled fixture during development of this skill,
reproducible with `scripts/slop_scan.py`:

- **vulture confidence cliff.** On a tree with genuine orphans: 12 findings at
  `--min-confidence 60` including live entry points, 0 at 80, 0 at 90. No
  setting produced a usable answer. Import-graph reachability found the real
  orphans with no false positives.
- **jscpd config sensitivity.** Duplication percentage ranged 28.99%-38.51% on
  identical code as `--min-tokens` varied from 20 to 100, non-monotonically.
- **Ratio metrics mislead on growing codebases.** Adding one near-identical
  service moved duplication from 28.57% to 20.48% while clone count went 2 → 3
  and duplicated lines 40 → 60. A percentage-based gate passes the commit that
  made things worse. This is why the ratchet gates absolutes.
